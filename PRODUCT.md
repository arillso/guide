# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Ansible users outside the project: DevOps engineers and sysadmins who find
arillso through Ansible Galaxy or GitHub. They arrive with a host to set up
(packages, firewall, Docker, K3s, monitoring agents) and need to judge
quickly whether an arillso role covers it, then look up its variables,
defaults and examples while writing a playbook.

## Product Purpose

guide.arillso.io is the reference documentation for the arillso projects:
the collections `arillso.system`, `arillso.container` and `arillso.agent`,
the `arillso/ansible` container image, the `action.playbook` GitHub Action
and the `go.ansible` library. Success: a visitor new to arillso understands
what it covers from the start page, and finds the option or example they
need on a role or module page without leaving the site.

## Positioning

One coherent set of roles for the base of a Linux host (system, container
runtime, host agents), plus arillso's own tools to run the same playbook
four ways: from a shell, from the `arillso/ansible` container image, from a
GitHub workflow (`action.playbook`) or from Go (`go.ansible`).

## Operating Context

- Visitors read while writing YAML: they copy role names, variable names
  and example blocks into their own playbooks.
- Collection pages (roles, modules, filters, lookups, option tables,
  return values) are generated by antsibull-docs from the released
  versions pinned in `versions.env`; Renovate bumps those versions.
- Hand-written pages under `rst/` cover the container image, the GitHub
  Action, the Go library and general guides.

## Capabilities and Constraints

- Collection documentation is generated with antsibull-docs from the
  versions in `versions.env`. No hand-written replacement of those pages.
- Sphinx builds with `-W`; every warning fails the build.
- Static site on GitHub Pages; every push to `main` deploys.

## Brand Commitments

- The name is always lowercase: "arillso", also in headings, navigation and
  the wordmark.
- Voice: factual. Every claim must be backed by the upstream repositories.
  No marketing phrasing ("production-ready", "battle-tested", "seamless").
- Open source, MIT licensed.
- Assets: `_static/logo.svg`, `_static/favicon.ico`.

## Evidence on Hand

- Real counts and versions: collection versions in `versions.env`; role,
  module, filter and lookup counts derived from the generated pages at build
  time.
- Real usage examples on the start page and the image, action and library
  pages.
- No testimonials, customer names, adoption figures, benchmarks or coverage
  numbers exist. Do not invent any.

## Product Principles

1. Reference first: the role and module pages are the product; everything
   else leads to them.
2. Show, then claim: a working playbook or command says more than a feature
   sentence.
3. Facts only: every number and statement traces back to an upstream repo
   or the build.
4. A newcomer must be able to tell within one screen what arillso covers.

## Accessibility & Inclusion

WCAG 2.2 AA contrast in light and dark mode, visible keyboard focus, usable
from 360 px viewport width.
